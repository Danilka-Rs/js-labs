## Цель данной лабораторной работы

Лабораторная работа №6 состоит из двух частей.

Первая часть лабораторной работы заключается в изменении механизма взаимодействия клиентской части с серверной частью. В прошлой лабораторной работе для выполнения AJAX-запросов использовался `XMLHttpRequest`, а в данной лабораторной работе используется более современный метод `fetch`.

В ходе выполнения работы необходимо познакомиться с асинхронностью в JavaScript, Promise, callback, `async/await`, методом `fetch`, а также научиться получать данные с backend и выводить их в интерфейс пользователя.

Вторая часть лабораторной работы заключается в сборке клиентской части приложения. Необходимо собрать frontend с помощью системы сборки Vite, а затем добавить в backend возможность раздачи собранной клиентской части в качестве статики.

Это позволяет запускать frontend и backend с одного сервера и уменьшает вероятность возникновения ошибок CORS.

## Дополнительные задания

### 1. Переделаны запросы через async, await и fetch

В предыдущей лабораторной работе запросы выполнялись через `XMLHttpRequest`. В данной лабораторной работе был реализован новый модуль для запросов, который использует `fetch`.

```js
class Ajax {
    async get(url) {
        try {
            const response = await fetch(url);
            return await this._handleResponse(response);
        } catch (error) {
            console.error("Fetch error (GET):", error);
            throw error;
        }
    }

    async post(url, data) {
        try {
            const response = await fetch(url, {
                method: "POST",
                headers: {
                    "Content-Type": "application/json"
                },
                body: JSON.stringify(data)
            });

            return await this._handleResponse(response);
        } catch (error) {
            console.error("Fetch error (POST):", error);
            throw error;
        }
    }

    async patch(url, data) {
        try {
            const response = await fetch(url, {
                method: "PATCH",
                headers: {
                    "Content-Type": "application/json"
                },
                body: JSON.stringify(data)
            });

            return await this._handleResponse(response);
        } catch (error) {
            console.error("Fetch error (PATCH):", error);
            throw error;
        }
    }

    async delete(url) {
        try {
            const response = await fetch(url, {
                method: "DELETE"
            });

            return await this._handleResponse(response);
        } catch (error) {
            console.error("Fetch error (DELETE):", error);
            throw error;
        }
    }

    async _handleResponse(response) {
        let data = null;

        try {
            data = await response.json();
        } catch (error) {
            data = null;
        }

        return {
            data,
            status: response.status,
            ok: response.ok
        };
    }
}

export const ajax = new Ajax();
```

В этом коде методы `get`, `post`, `patch` и `delete` выполняют HTTP-запросы к серверу.

Метод `_handleResponse` обрабатывает ответ сервера. Он получает JSON-данные, статус ответа и флаг `ok`, который показывает, успешно ли завершился запрос.

Такой подход удобен, потому что вся логика работы с запросами находится в одном файле.

## Теоретическая часть

### Асинхронность

Асинхронность — это возможность выполнять операции, которые занимают время, не блокируя работу всей программы.

Например, запрос к серверу не выполняется мгновенно. Если бы страница ждала ответ сервера синхронно, интерфейс мог бы зависнуть. Асинхронность позволяет отправить запрос, продолжить работу страницы, а ответ обработать позже.

В данном проекте асинхронность используется при получении кэшбэк-предложений с backend.

### Callback

Callback — это функция, которая передаётся в другую функцию и вызывается позже, после завершения какой-либо операции.

Пример:

```js
ajax.get(url, (data, status) => {
    console.log(data);
});
```

В этом случае функция `(data, status) => { ... }` выполнится после того, как сервер вернёт ответ.

В предыдущей лабораторной работе callback использовался вместе с `XMLHttpRequest`.

Основной недостаток callback заключается в том, что при большом количестве асинхронных операций код может стать сильно вложенным и сложным для чтения.

### Promise

Promise — это объект, который представляет результат асинхронной операции.

Promise может находиться в трёх состояниях:

```text
pending — ожидание;
fulfilled — успешное выполнение;
rejected — ошибка.
```

Promise позволяет обработать результат асинхронной операции через `.then()` и `.catch()`.

Пример:

```js
fetch("/cashbacks")
    .then(response => response.json())
    .then(data => console.log(data))
    .catch(error => console.error(error));
```

### Отличие callback от Promise

Callback — это функция, которую вызывают после завершения операции.

Promise — это объект, который хранит состояние асинхронной операции и позволяет обработать успешный результат или ошибку.

Кратко:

```text
Callback — передаём функцию, которую вызовут позже.
Promise — получаем объект, который завершится успехом или ошибкой.
```

В контексте лабораторных работ:

```text
ЛР №5 — XMLHttpRequest + callback.
ЛР №6 — fetch + Promise + async/await.
```

### async/await

`async/await` — это удобный синтаксис для работы с Promise.

Если функция объявлена как `async`, внутри неё можно использовать `await`.

```js
async function loadCashbacks() {
    const response = await fetch("/cashbacks");
    const data = await response.json();

    console.log(data);
}
```

`await` ожидает выполнение Promise и позволяет писать асинхронный код так, будто он обычный последовательный код.

При этом браузер не зависает полностью. Ожидает только конкретная асинхронная функция.

### fetch

`fetch` — это современный встроенный метод браузера для выполнения HTTP-запросов.

Он используется вместо `XMLHttpRequest`.

Пример GET-запроса:

```js
const response = await fetch("/cashbacks");
const data = await response.json();
```

Пример POST-запроса:

```js
const response = await fetch("/cashbacks", {
    method: "POST",
    headers: {
        "Content-Type": "application/json"
    },
    body: JSON.stringify(newCashback)
});
```

`fetch` возвращает не сами данные, а объект `Response`. Чтобы получить данные из тела ответа, нужно вызвать:

```js
response.json()
```

### Отличие fetch от XMLHttpRequest

`XMLHttpRequest` — более старый способ выполнения AJAX-запросов. Он работает через объект запроса, события и состояния.

`fetch` — современный способ выполнения HTTP-запросов. Он возвращает Promise и удобно используется вместе с `async/await`.

Основное отличие:

```text
XMLHttpRequest — события, readyState, callback.
fetch — Promise, then/catch, async/await.
```

### JSON

Backend отдаёт данные в формате JSON.

JSON — это текстовый формат обмена данными.

Пример объекта кэшбэк-предложения:

```json
{
  "id": 1,
  "title": "Кэшбэк на маркетплейсы",
  "rate": "10%",
  "category": "Покупки"
}
```

После получения ответа frontend преобразует JSON в JavaScript-объект или массив с помощью:

```js
await response.json()
```

### HTTP-статусы

HTTP-статус показывает результат выполнения запроса.

В проекте используются следующие статусы:

```text
200 — запрос выполнен успешно;
201 — объект создан;
204 — запрос успешен, но тело ответа пустое;
404 — объект не найден;
500 — ошибка сервера.
```

Например, если пользователь открывает карточку, которой нет, backend может вернуть статус `404`.

Если карточка успешно удалена, backend может вернуть статус `204`.

### REST API

Backend предоставляет REST API для работы с кэшбэк-предложениями.

Основные маршруты:

```text
GET /cashbacks — получить все кэшбэк-предложения;
GET /cashbacks/:id — получить одно предложение;
POST /cashbacks — создать новое предложение;
PATCH /cashbacks/:id — изменить предложение;
DELETE /cashbacks/:id — удалить предложение.
```

REST API удобно тем, что каждое действие связано с конкретным HTTP-методом.

### Vite

Vite — это инструмент для запуска и сборки frontend-приложений.

Он используется для разработки и подготовки проекта к запуску на сервере.

В режиме разработки Vite запускает frontend на отдельном порту:

```text
http://localhost:5173
```

После сборки frontend превращается в набор обычных статических файлов: HTML, CSS, JavaScript и изображения.

### Статика

Статические файлы — это файлы, которые сервер отдаёт пользователю без дополнительной обработки.

К ним относятся:

```text
HTML;
CSS;
JavaScript;
изображения.
```

В данной лабораторной работе собранный frontend помещается в папку `public`, а backend отдаёт эту папку через `express.static`.

### CORS

CORS — это механизм безопасности браузера, который ограничивает запросы между разными источниками.

Например:

```text
frontend: http://localhost:5173
backend:  http://localhost:3000
```

Для браузера это разные источники, потому что отличаются порты.

После сборки frontend можно открыть через backend:

```text
http://localhost:3000/
```

И API будет находиться на том же адресе:

```text
http://localhost:3000/cashbacks
```

Такой подход уменьшает вероятность возникновения проблем с CORS.


Frontend отправляет запрос:


Если карточка не найдена, backend возвращает статус `404`.

Для удаления карточки используется запрос:


Если удаление прошло успешно, backend возвращает успешный статус, например `204`.
